# Core Code Map for Interviews

This map names the modules that carry the project’s real engineering ownership. It deliberately records limitations and likely change requests instead of presenting every module as production-ready.

| Core module | Why it exists / input → output | Core algorithm | Likely bug and current limit | Safe interview modification |
| --- | --- | --- | --- | --- |
| `ObservationCompressor` | Reduce a framework-neutral Observation while preserving interactive and semantic nodes. | Normalize → prune invisible/empty structure → conservative duplicate merge → materialize depth/priority and stats. | Over-pruning a wrapper can hide a target; malformed trees need bounded handling. | Add a fixture for a clickable empty node or a duplicate subtree and prove actionability is preserved. |
| `ProductParser` + `QuantityParser` | Convert one title into identity, package quantity and components. | Deterministic regex candidates, unit normalization to ml/g, explicit gift separation, ambiguity status. | SKU numbers can resemble quantities; combined titles still need semantic evidence. | Add a new unit or an ambiguity rule with a representative fixture, not a product-specific hardcode. |
| `PriceParser` | Separate page-displayed prices from derived prices. | Candidate extraction, kind classification, rank by label semantics, conflict detection, `PriceEvidence`. | Dynamic/starting/member prices cannot prove a unique comparable price. | Add a price kind and a regression proving the parser abstains instead of selecting the minimum. |
| `PricingEngine` | Calculate effective price without letting an LLM guess. | Decimal arithmetic over confirmed `PricingRule`; threshold, fee and membership boundaries fail closed. | A threshold needs an order subtotal; current fixtures only prove limited cases. | Add a rule with explicit condition evidence and a test for unresolved conditions. |
| `ComparisonEngine` | Match normalized offers and recommend only comparable prices. | Identity/spec/quantity matching, effective unit price, no forced recommendation below two resolved offers. | Cross-platform identity and live price volatility remain limited by evidence. | Add a comparison-confidence threshold or a new mismatch reason while keeping no-recommendation behavior. |
| `HybridProductParser` | Use a structured LLM only when rule confidence is insufficient. | Pydantic schema validation, one bounded fallback, rule fallback on provider/schema failure. | FakeLLM replay can hide online model errors; low-confidence output must abstain. | Add a malformed/low-confidence response and assert the safe fallback. |
| `ActionGrounder` / `StaleObservationGuard` | Bind actions to current UI state. | Stable resource/node/text matching, observation-id validation, fresh observation after important actions. | Node IDs and coordinates are not durable page fingerprints. | Add a changed-visible-text case and reject the stale action. |
| `SafetyGuard` | Prevent order/payment/security actions independently of prompts. | Deterministic blocked-term and page-boundary assessment. | New platform wording can evade a term list; broad matching must not block harmless browsing. | Add a narrowly scoped safety phrase and preserve SAFE MODE behavior. |

Evidence references: `backend/tests/test_product_parser.py`, `backend/tests/test_pricing.py`, `backend/tests/test_comparison.py`, `backend/tests/test_web_adapter.py`, the frozen evaluation reports, and the Mock Android/Browser acceptance reports. These references prove controlled behavior only; they do not prove live e-commerce success.
